## 开场：约一分钟说明项目

“本项目研究的是：在共享同一个解析工具位置跟踪器的条件下，学习到的次级姿态控制器能否比调优后的人工势场提高完整轨迹的无碰撞成功率。我们使用 PyBullet 固定基座 Panda，控制七个臂关节、保持手指目标固定，按规定时间执行一条三维平滑直线，并加入一个几何已知的静态球障碍。

三个控制器分别是只有跟踪器、跟踪器加势场、跟踪器加 PPO。它们共用机器人、初始状态、物理约束、主任务和执行接口。PPO 只能给有界的七维次级速度调整，不能修改参考路径、时长或暂停时钟。我们用逐物理步的误差、几何碰撞和关节限位检查定义成功，另外保存可在同样条件下重放的 joint-motion witness。研究重点是公平比较和失败机制，不是预先证明 RL 一定更好。”

实际结论：“在冻结的100个相同测试场景上，tracker成功70次、APF92次，三个PPO seed为80、81、65次。PPO在紧布局上超过tracker，但未超过APF，而且在简单布局引入额外失败。本预算与筛选分布下不支持RL整体优于APF。”

## 思维模型一：Jacobian 是局部速度映射

输入是当前关节姿态 `q∈R⁷`（rad）和小关节速度 `qdot∈R⁷`（rad/s），输出是工具点世界速度 `xdot∈R³`（m/s）：`xdot=J(q)qdot`，其中 `J` 为 `3×7`，单位 m/rad。它描述当前姿态的一阶关系，既不是从任意关节角直接求位置的函数，也不是一条全局规划路径。

Panda 模型实际有七个旋转臂关节和两个移动手指自由度。完整 Jacobian 有九列；代码按可动自由度元数据抽取七个臂关节列。工具为模型中 `panda_grasptarget` 的 link 原点，位置和 Jacobian 必须指向同一个工具点、坐标系和关节顺序。不能把“矩阵形状正确”当成“列含义正确”。

验证使用多个姿态的中心有限差分。此时 `resetJointState` 是诊断操作；正式执行不能靠重置状态推进。有限差分误差还受扰动幅度、输出精度和局部线性化影响，扰动越小不一定越准。

**口述句：**“我先验证 Jacobian 对应的是实际使用的工具点和关节列，再讨论控制器；否则正确的线性代数也可能控制了错误的点。”

**深入追问：**如果工具点沿手掌偏移 5 cm，说明原 Jacobian 哪些部分需要改变；如果奇异值变小，说明为什么同样工具速度可能需要更大关节速度。

**常见错误与工程检查：**把 Jacobian 当成位置映射；手指不控制就删掉对应物理几何；只在一个姿态做差分；把零动作的零泄漏当成投影验证。最小实践是打开一次 Jacobian 诊断和一条非零次级命令记录，核对形状、单位与 `||JNu||`。

## 思维模型二：主次任务共享同一套执行能力

跟踪器先形成世界坐标任务速度：

\[
v_{task}=\dot x_{ref}+K_p(x_{ref}-x),\quad
\dot q_{raw}=J^{\#}v_{task}+Nu.
\]

`Kp` 单位 1/s；`J#` 为 `7×3` 的阻尼最小二乘逆；`u` 为七维 rad/s 次级命令；`N` 为 `7×7` 无量纲矩阵。参考速度提供前馈，位置误差项纠偏。主任务用 SVD 的奇异值变换 `s/(s²+λ²)`，减小近奇异放大；次级投影另用零空间基 `Vnull` 构造 `N=Vnull Vnullᵀ`。

当 `rank(J)=3` 时通常有四维零空间，但 PPO 的 action 仍是七维，统一接口将它投影进去；它并没有七个额外自由运动方向。所有控制器都经过相同的次级限幅、合成速度限幅、力矩限制和电机。投影只约束当下的几何速度，不能保证步进后的真实跟踪或碰撞安全。

势场从整条机械臂、手和手指的最近碰撞几何得到净空和法向。球静止时距离梯度为 `∇q d=nᵀJA`；自碰撞对是 `nᵀ(JA−JB)`。这里 `n` 从对象 B 指向 A，`JA/JB` 是对应最近点的位置 Jacobian。接近作用范围内时叠加远离障碍、自碰撞及软关节边界的次级项；近距离用有限下界限制斥力幅值，再通过与 RL 完全相同的接口投影和执行。最近特征切换时只分段可微，局部梯度不是全局避障证明。

**口述句：**“我们把主任务的阻尼数值稳定性和次级任务的零空间几何分开处理；随后仍以实际电机 rollout 判断是否满足任务。”

**深入追问：**若 `JNu≈0` 而误差升高，应依次检查饱和扰动、电机执行误差、局部积分/秩变化及碰撞；不应直接宣布 Jacobian 或 RL 错了。

**常见错误与工程检查：**把 `I−J#J` 在带阻尼时称为严格投影；只看末端到球心；忽略朝向自由变化带来的手部碰撞；把调过 12 组参数称为全局最优势场。最小实践是选择同一失败时刻，对齐原始命令、提交电机的命令、实测速度和饱和标志。

## 思维模型三：一回合是一份带时钟的合同

输入是初始状态、规定时长的平滑直线和静态球几何；输出是完整轨迹成功标志及逐步证据。当前参考使用 quintic 时间律，固定 4 s。策略每四个物理步更新一次动作，但主任务与安全判据仍每个 1/240 s 更新。零 action 也会继续执行解析轨迹，策略不能让任务时间停止。

成功要求：初态和每个物理步后，误差都不超过 20 mm、没有禁止碰撞、没有关节边界违反，并完成原定时间。当前碰撞判据是有符号几何距离 `≤1e−5 m`；关节边界允许 `1e−4 rad` 的数值带。碰撞、自限位、数值失效可提前结束；跟踪超差永久锁存失败但继续到时限。即使最后回到路径，也不能擦除中途违约。离散检查不会证明两次采样之间绝无接触。

Gym 中任务完成或安全失败是 `terminated`，外部资源步数上限才是 `truncated`。轨迹进度包含在 observation 中。55 维 observation 覆盖关节状态、误差、期望运动、进度、三个未来参考点、球几何、上一实际电机命令及全局/逐 link 净空；使用固定物理尺度，不在 test 更新归一化。PPO 输入 `(55,)`，七维高斯策略的采样/预测结果经 `[-1,1]` 裁剪后才进入环境，不能把原始高斯分布称为有界；当前网络为 64×64 MLP。reward 逐物理步积分跟踪、净空和命令变化，成功奖与失败罚独立于“最后是否到终点”。

**口述句：**“主要指标不是最终到达，而是在规定时间内整段轨迹始终满足约束；失败标志一旦置位就不会恢复。”

**深入追问：**解释为什么有限任务的终点不是机械地归为 TimeLimit 截断；为什么网络看到上一命令后还需要实测 `qd`；为什么 reward 上升可能伴随成功率不升。

**常见错误与工程检查：**将速度命令等同实测速度；只每 60 Hz 检碰撞；碰撞早结束后以更低 RMSE 宣称更好；把奖励设计成“自杀少受罚”。最小实践是查看一个失败 episode 的首个违规时间、参考时间、终止类型和最终 `success`，不必等待答题才继续工程。

## 思维模型四：witness 是存在一条实际执行路径的证据

输入是候选场景与有限的候选控制方法；输出是可完整物理重放的关节运动/电机目标记录，或者“尚未验证可行”。离线姿态重置可以帮助放置障碍和搜索候选，但接受场景必须从相同初态、按相同轨迹时间和限制，实际调用电机及 `stepSimulation` 重放通过。离散 IK 解只表示一组姿态存在，不证明相邻姿态能按规定时间连接。

当前生成器使用 tracker、默认势场及 seeded constant-secondary 的候选集合，只要某个候选成功并重放通过即可提供 witness；不要求 PPO 成功才接受。被拒绝或没有找到 witness 的候选仍有原因日志。witness 不输入策略，也没有自动引入行为克隆或模仿学习。

这样的数据集仍是“在该有限搜索方法下被验证可行”的条件样本，不是所有可行布局的均匀样本。多个 witness 方法降低对单一控制器的直接依赖，却不能消除筛选偏差。证明有解与证明无解在逻辑上不对称：一次成功执行足以证明本配置下存在执行；几次搜索失败不足以证明不存在。

**口述句：**“witness 的作用是避免把未知可行性与控制器失败混在一起；它提供正面的执行证据，但我们的搜索不具有完备性。”

**深入追问：**如果某一 witness 方法占多数，应怎样描述数据分布；为什么不能为了凑齐 test 数量临时放宽容差或障碍参数。

**常见错误与工程检查：**用状态重置动画代替物理 witness；看到所有候选失败就标记不可行；把成功控制序列泄漏给 policy。最小实践是核对一个 witness 的配置 hash、完整命令数量、重放通过记录及源轨迹/重放轨迹的对应关系。

## 思维模型五：可信比较来自同等条件和未见数据

训练用 train，势场参数和 PPO checkpoint 只用 validation。固定 test 的作用是估计这些选择完成之后的效果；test 场景、机器人约束、基线参数、模型 hash、统计规则和代码版本冻结后才做比较，不根据测试结果回调难度或参数。三个独立训练 seed 是三次训练，不是把一个模型复制三份，也不是同一模型重复评估三次。

主指标始终以所有固定场景为分母，包括很早失败的回合。辅助指标包含碰撞、误差、最小净空、命令变化/平方加速度积分、饱和率、时长与在线耗时。早失败回合只能报告它执行过的前缀，不能因为轨迹短就宣称总体更平滑。跨控制器连续指标如只在共同完成场景比较，必须标“条件比较”并给出样本数。

每个 PPO seed 对同样 100 场景做配对比较，分别报告简单/较紧布局。训练 seed 的差异说明优化/采样过程波动；场景抽样区间反映固定模型对场景总体的估计误差，两者不能混成一个误差条。三个 seed 很少，不能据此保证训练方差估计稳定。计时明确包含特征、策略推理、控制计算和物理步进中的哪些部分，渲染时间另报。

**口述句：**“我们的结论来自冻结场景上的配对比较，并保留失败分母；视频只展示行为，不承担成功率证据。”

**深入追问：**同样 100 个场景上两个控制器各成功 80 个，为什么还需要知道哪 80 个；为什么 success-conditioned RMSE 低不能自动说明更好的总体控制。

**常见错误与工程检查：**test 参与 checkpoint 选择；将跨 seed 和跨场景的不确定性混为一谈；挑最好 seed 作为全部 RL 结论；把一次优秀视频当泛化证明。最小实践是从冻结清单追到模型 hash、场景 ID、逐 episode CSV/JSON 和汇总图，检查是否能重建主分母。

## 三个关键争议：回答时保留条件

**1. 严格零空间与阻尼鲁棒性是否矛盾？**

主任务 DLS 用阻尼控制病态放大，代价是任务速度偏差；次级项用独立 SVD 零空间，在所选数值秩下保持一阶零泄漏。这让两个目标分开处理，但不产生物理安全保证。秩阈值变化、离散积分、合成后裁剪和电机响应仍可能破坏跟踪。可以用日志中的奇异值、投影泄漏、裁剪扰动与真实误差定位问题。避免说“严格零空间所以绝不影响主任务”。

**2. RL 是否真的学会提前规划，而不是记住训练布局？**

未来参考和已知障碍使提前姿态调整成为可能，但这只是设计动机。真正证据应来自未见布局上的行为与总体结果，且与调优势场保持相同执行权限。没有独立“去掉 future-reference”的训练消融，不能从总体收益中分离出未来输入的因果贡献。若 RL 没赢，应检查训练预算、奖励信号、动作空间冗余、筛选分布和局部势场已足够有效等解释；这些是后续假设，不能靠想象指定唯一原因。

**3. 验证可行的数据集是否已经偏向传统方法？**

存在这种可能。当前集合是多种有限 witness 搜索的并集，仍偏向这些方法能找到解的区域。需要披露方法覆盖与拒绝原因，并把结论限定在本生成分布。测试场景的 witness 生成可以在隔离流程里进行，但其候选控制器结果不能被用于基线调参、模型选择或改变难度。只有扩大独立可行搜索方法、验证新分布或更系统的可行性方法，才能评估这个偏差；当前不能宣称已完全消除。

## 用真实失败回答，而不是替结果找借口

固定seed144的APF/PPO配对计数：共同成功74、APF成功而PPO失败18、PPO成功而APF失败6、双方失败2。可从每一类字典序最先场景检查行为；现有视频展示study-4490-0017与study-4490-0069两种相反结果。每个案例沿同一条证据链说明：场景几何 → 首个违规时间 → 命令/饱和/实际速度 → 最近碰撞 link 或超差 → 对研究问题的含义。未完成的案例不能混入完成轨迹的误差优势。

可用口述结构：“这个回合在 t=… 首先触发…，不是因为最后位置…。在违规前…的日志显示…，所以数据支持…这一解释；还不能排除…，要区分它需要…。” 当前已有上文两个正式 test 案例，以及 [failure_analysis.md](failure_analysis.md) 中三个限位案例；填写数字时必须追溯对应场景与轨迹，不把示例模板当作证据。

若 RL 未超过势场，可说：“在这次固定训练预算与 witness 筛选分布下，没有观察到学习控制器优于调优势场的证据。我们保留所有失败，分析差异集中在哪些布局，并将训练预算/奖励/场景分布作为待验证原因。这不是对所有 RL 方法或所有布局的否定。” 若观察到优势，也必须限定分布、训练 seed 和不确定性，不能直接外推到实机安全。
