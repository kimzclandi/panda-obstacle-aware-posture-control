# Gymnasium / PPO：当前 pilot 的实际契约

本页描述实现选择，不把它们当作 proposal 已固定的算法，也不等于正式 RL 实验已经完成。实测结果须引用独立实验目录。当前环境使用 `ControlTask`，与 tracker、势场、witness replay 共用机器人、电机约束、位置主任务和安全检查。

## 1. 时间、动作与终止

输入为七维 `action ∈ [-1,1]^7`，无量纲。共享 `bounded_secondary` 将它缩放至 `secondary_speed_limit` rad/s，再经过 SVD 零空间投影、与解析位置主任务相加、统一电机速度裁剪，最后由速度电机和 `stepSimulation` 执行。动作不是关节目标位置，也不是对参考路径的修改。

默认物理/主跟踪频率为 240 Hz，策略频率为 60 Hz，即 `action_repeat=4`。次级动作在这四个物理步保持不变，但 Jacobian、跟踪误差和主任务命令逐物理步重算。每个物理步后检查全部安全条件；最后一个策略步可以不足四个物理步。参考时钟只随物理步前进，策略没有暂停或改速权限。当前数据中的统一执行参数以保存的 config 为准。

有限轨迹到达规定终点，或碰撞/关节限位/数值失效，均为 `terminated=True`。跟踪超差会永久锁存失败，但不会提前停止参考时钟；后来回到路径不能恢复成功。外部 `external_max_steps` 提前切断本可继续的任务时为 `truncated=True`，不添加任务终止奖惩；用于测试资源上限，不用于当前训练。Gym/SB3 可对外部截断 bootstrap，对有限任务终止不 bootstrap。轨迹进度作为 observation 避免隐藏有限时域。

初始态若已不安全，`reset` 抛出带原因的异常，不悄悄重采样并丢弃失败场景。训练入口只接受有物理 replay 成功记录的场景。独立固定场景评估仍保留所有实际失败回合。

## 2. 55 维 observation

所有向量按行连接为 float32 `(55,)`。下表切片遵循 Python 的左闭右开区间；没有运行中的均值/方差估计，因此 validation/test 不会更新归一化统计。所有距离/位置向量都在固定基座对应的世界坐标系中。最后统一裁剪至 `[-10,10]`，原始物理数据仍保留在轨迹中。数值失效终止态中 NaN/Inf 被转换为有限 observation，失败标志不会清除。

| 切片 | 特征与原始单位 | 固定变换 | 必要性 |
|---|---|---|---|
| 0:7 | 关节角 `q`，rad | `(q-mid_limit)/half_limit_range` | 当前姿态、冗余自由度、与限位的关系 |
| 7:14 | 实测关节速度 `qd`，rad/s | 除以共享各关节速度上限 | 区分同姿态下不同运动状态 |
| 14:17 | `xref-x`，m | 除以跟踪容差 | 次级动作必须兼顾主任务误差 |
| 17:20 | 当前参考速度 `vref`，m/s | 除以 0.2 m/s | 区分参考运动方向和强度 |
| 20:21 | 轨迹进度 | `t/duration`，范围 0–1 | 有限任务时间及终止位置 |
| 21:30 | 未来 0.25/0.5/1.0 s 的参考位置减当前工具位置，m | 除以 0.25 m | 给姿态预调整提供未来几何；越过轨迹终点时固定取终点 |
| 30:33 | 球心位置，m | 除以 1 m | 已知静态障碍的世界几何 |
| 33:34 | 球半径，m | 除以 0.2 m | 区分障碍尺寸 |
| 34:35 | 是否存在球障碍 | 0 或 1 | 支持无障碍工程诊断；没有球时 30:35 全零 |
| 35:42 | 上一实际提交电机的限幅速度目标，rad/s | 除以共享各关节速度上限 | 历史执行命令及平滑性；不是上一 raw action 或测得速度 |
| 42:43 | 最小允许检查的自几何净空，m | 除以 0.1 m，再裁剪到 `[-1,1]` | 提示自碰撞风险 |
| 43:44 | 最小全臂/手/指到球的净空，m | 除以 0.2 m，再裁剪到 `[-1,1]` | 全局障碍风险；无球记为 1 |
| 44:55 | 十一个碰撞 link 各自到球的最近净空，m | 查询上限 0.2 m，除以 0.2 m，裁剪到 `[-1,1]` | 区分哪个臂段/手部接近障碍；没有球时全 1 |

十一个 link 的顺序来自加载模型的 `collision_links`，并在 model 元数据中保存；环境校验 link 数量，没有硬猜关节索引。球净空通过真实碰撞几何的 `getClosestPoints` 计算，含基座、臂段、手掌、手指。超过查询半径只表示“至少达到查询上限”，不是精确远距离。关节角和机器人模型同时编码自碰撞几何，不向策略提供 witness、测试标签、策略 ID 或专家动作。

当前统一时长与执行器参数固定。若以后混合不同机器人/力矩限制/时长，必须重新检查 observation 是否足以描述状态，不能直接假设 MDP 契约仍成立。手指位置伺服与接触动力学也使这个低维状态只是工程近似；本项目不声称精确观测了模拟器的每个内部状态。

## 3. Reward 与可检查边界

每个物理步积分一个有界 reward rate，然后在策略步汇总。不能只取每四步的末帧，否则会漏掉中途危险。令 `e` 为位置误差范数，`ε` 为跟踪容差，`d` 为自碰撞与球净空的较小值，`m=0.05 m`，`v_k` 为实际电机速度目标，`vmax` 为共享速度上限：

\[
 r_k=\Delta t\left[1
 -2\min((e/\epsilon)^2,1)
 -2\operatorname{clip}((m-d)/m,0,1)^2
 -0.1\min\left(\operatorname{mean}\left[((v_k-v_{k-1})/v_{max})^2\right],1\right)\right].
\]

代码中平滑项的精确定义是 `mean(((v_k-v_{k-1})/vmax)**2)`，即先对七个元素平方再取平均。这里惩罚归一化命令变化，是 pilot 奖励塑形；它不是以 rad²/s³ 计量的报告平滑度指标，也没有替代评估中的命令平方加速度积分。

每秒运行 reward 范围为 `[-3.1,1]`。完整成功时加 20；任务失败时减 `20 + 3.1 × 剩余参考时间秒数`。额外未完成时长罚项覆盖通过早失败跳过的最大负运行 reward，降低“碰撞自杀来躲开后续惩罚”的显然诱因。对当前 4 s 时域，完整成功的保守回报下界为 7.6，而任何失败的乐观上界不超过 −16。因此当前奖励使完整成功优于失败的整个回报边界可检查，**这仍不证明 PPO 一定找到成功策略，也不排除在失败策略之间学到次优习惯**。若时长或权重变化，需要重新计算边界。

净空项含结构上本来较近的合法自碰撞对，可能产生近乎常数的负项或与障碍信号竞争，须通过 pilot 学习曲线及行为审查评估。固定路径移动会让“停住”产生跟踪罚并最终失败；policy 本身不能关闭解析跟踪器，但可通过恶劣次级动作/饱和干扰它。振荡受命令变化罚项约束，但可能利用未足够惩罚的小幅快速变化。必须检查完整失败率、饱和率、动作变化、轨迹与回报，而非只看 reward 上升。当前没有做独立“无 future-reference”训练，不能把任何收益单独归因于未来参考。

## 4. PPO pilot 与模型选择

`train.py` 默认 CPU、Torch 单线程、64×64 MLP；PPO rollout=512 policy steps，batch=64，epochs=10，learning rate=3e−4，gamma=0.995，GAE lambda=0.95，clip=0.2，entropy coefficient=0.01。默认短试验 8192 policy steps；步数可能向上取整到完整 rollout。算法与依赖版本记录在 `provenance.json`。这些是开发选择，不是已调优最优参数。

数据入口显式只消费 train 和 validation。所有 ID、物理配置 hash 校验唯一，避免改 ID 后跨 split 复制同一任务；manifest/config 元数据必须一致，且必须存在 `witness.replay_passed=true`。该检查依赖场景生成器留下的证据链，不能仅靠手写布尔值证明动态可行。正式场景冻结时仍应校验 witness 文件完整性和重放记录。

训练只使用 train 的随机场景；checkpoint 选择遍历完全相同的所有 validation 场景、确定性动作、无观测统计更新。排序依次为：成功率高、碰撞率低、完成率高；完全相同时保留最早的**已训练** checkpoint。step 0 的未训练策略只作诊断，不可作为 `best_model`。不同 checkpoint 的 completed-only RMSE 仍报告条件样本数，但不用于选模，因为子集可能不同。test 不参与此流程。

每次 run 独立保存：参数/数据 hash/代码和依赖快照、实际消费场景、Monitor 回报、各 checkpoint 的全量 validation episode 结果、最优/最终模型、保存加载动作一致性检查，以及在新环境中加载最优模型后的独立 validation 轨迹。训练中 validation 只有逐回合指标，最终独立重放保存全部逐步轨迹。验证失败回合保留在分母。

SB3 的逐步 callback 在采样期间触发，先于该 rollout 的优化更新。因此训练结束必须在最后一次更新之后再评估，即使 policy-step 计数相同也不能跳过。当前实现将此轮保存为单独的 `validation_step_<N>_final_after_update/`，history 记录 `phase` 与已完成 optimizer epochs，并允许该最后模型参与既定选模。首轮 pilot 进程若在修正前已启动，需单独补做最终模型验证并记录独立证据，不能回写旧结果冒充最初流程已包含它。

`training_summary.json` 区分含 callback validation 的学习墙钟、减去 validation 的估计训练墙钟、实际 policy steps 吞吐；据此线性推算三 seed × 一百万步所需小时，不包括后续 validation/test/调参/视频，也不保证该预算足以收敛。网络推理与 observation 特征计算另计，PyBullet 在 CPU 执行。独立评估的控制/物理计时以 `ControlTask.summary` 定义为准；Gym 环境的 `secondary_decision` 没有网络时间，不能误当整体在线延迟。
